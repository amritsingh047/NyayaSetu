LegalLens

GenAI-Powered Legal Assistance Platform — Product & Technical Plan

Core Principle: LegalLens provides legal information and document comprehension — it does not provide legal advice. Every output includes a disclaimer encouraging users to consult a licensed attorney for binding guidance.

Project Overview

LegalLens is a platform that helps individuals and small businesses understand, compare, and navigate legal documents using generative AI. It translates dense legal language into plain English, highlights obligations and risks, and answers questions grounded in the user's own documents — all while making clear that it is not a substitute for professional legal counsel.

Target Users

Individuals reviewing leases, employment agreements, or terms of service before signing. Small business owners comparing vendor contracts, NDAs, or partnership agreements. Freelancers and contractors evaluating scope-of-work clauses. Anyone who needs to understand what a legal document actually says before deciding whether to consult a lawyer.

Phased Delivery

Phase 1 — MVP Weeks 1–8

Core document comprehension: upload, summarize, highlight clauses, contextual Q&A, glossary, and action-item extraction. Single-document focus, essential safety disclaimers, local-first processing option.

Phase 2 — Compare & Customize Weeks 9–16

Side-by-side contract comparison, jurisdiction-aware templates, entity recognition, redaction tools, confidence calibration improvements, and multi-document support.

Phase 3 — Collaborate & Integrate Weeks 17–24

Collaborative review workflows, annotations, sharing with legal professionals, e-signature integrations, document management connectors, and advanced analytics.

Key Architectural Decisions

RAG over Full-Context for Long Documents

Documents are chunked (by clause/section boundaries when possible, falling back to ~500-token overlapping windows) and embedded. Q&A and analysis use retrieval-augmented generation to stay within context limits and ground responses in specific passages. For short documents (<8k tokens), the full text is passed directly.

Guardrail-First Pipeline

Every LLM call passes through the Guardrail Engine before reaching the model. This layer injects the disclaimer system prompt, checks that the user query is within scope (document comprehension, not jurisdiction-specific legal advice), and post-processes outputs to attach confidence indicators and source references.

Local-First with Cloud Option

The default deployment processes documents locally (the LLM call is the only external service). Users can opt into cloud processing for faster analysis of large documents. All cloud processing is ephemeral — document data is purged after the session unless the user explicitly saves it.

Why This Stack

The combination of Python/FastAPI on the backend with Claude as the LLM plays to the strengths of both: FastAPI's async capabilities handle concurrent document processing well, and Claude's large context window means shorter documents can be analyzed in a single pass without chunking overhead. PostgreSQL with pgvector avoids the operational complexity of a separate vector database while still supporting efficient semantic search for longer documents. The legal-domain embedding model (voyage-law-2) significantly improves retrieval quality for clause-level Q&A compared to general-purpose embeddings.

For the frontend, Next.js provides server-side rendering for the initial document view (important for perceived performance when loading large analysis results) while React handles the interactive elements like clause highlighting and the Q&A interface. Tailwind and shadcn/ui keep the UI development fast without sacrificing accessibility.

MVP Feature Set

The MVP delivers four core capabilities that together form a complete document comprehension workflow: upload a document, get a plain-language summary, explore individual clauses with explanations, ask questions about the document, get a glossary of legal terms, and receive actionable takeaways. All six features in the MVP scope below.

MVP Feature 1 — Plain-Language Summary

US-01: Generate Document Summary

As a small business owner, I want to upload a contract and receive a plain-language summary, so that I can quickly understand what the document says without reading every clause.

Acceptance Criteria: Summary is generated within 15 seconds for documents under 20 pages. Summary covers the parties, purpose, key obligations, term/duration, and notable conditions. Confidence level is displayed (high/medium/low). A disclaimer is shown below every summary. Source excerpts are linked for each summary point.
US-02: Adjust Summary Depth

As a user, I want to choose between a brief overview (3–5 sentences) and a detailed breakdown (section-by-section), so that I get the level of detail I need.

Acceptance Criteria: Toggle between "Quick Overview" and "Detailed Breakdown" modes. Detailed mode produces a section-by-section walkthrough. Both modes include confidence indicators.

MVP Feature 2 — Clause Highlighting & Explanation

US-03: Highlight and Explain Clauses

As a freelancer reviewing a contract, I want to see key clauses highlighted with color-coded risk levels and click on any clause for a plain-English explanation, so that I understand my obligations and risks.

Acceptance Criteria: Clauses are categorized as obligations, rights, risks, or conditions. Each category has a distinct visual indicator. Clicking a clause opens a side panel with: plain-language explanation, risk assessment (low/medium/high), what options the user might have, and the exact source text. At least 80% of substantive clauses are detected and categorized.

MVP Feature 3 — Contextual Q&A

US-04: Ask Questions About a Document

As a tenant reviewing a lease, I want to ask natural-language questions like "Can my landlord raise the rent mid-lease?" and get an answer grounded in my specific document, so that I understand how the document applies to my situation.

Acceptance Criteria: Answers reference specific sections/clauses from the uploaded document. If the document doesn't address the question, the system says so rather than guessing. Relevant excerpts are shown alongside the answer. The system declines to give jurisdiction-specific legal advice and suggests consulting an attorney when the question goes beyond document comprehension.
US-05: Follow-Up Questions

As a user, I want to ask follow-up questions that build on previous answers within the same session, so that I can explore a topic in depth without re-explaining context.

Acceptance Criteria: Conversation history is maintained within a session. Follow-ups correctly resolve references like "that clause" or "the termination section." Session context is clearable by the user.

MVP Feature 4 — Action Items & Checklists

US-06: Generate Action Items

As a small business owner about to sign a vendor contract, I want to receive a checklist of things I need to do, deadlines I need to meet, and conditions I should verify, so that I don't miss critical obligations.

Acceptance Criteria: Action items are extracted from obligation and condition clauses. Each item includes the source clause reference, the deadline or trigger (if any), and a priority level. Checklist is downloadable as a PDF or markdown file.

MVP Feature 5 — Legal Glossary

US-07: In-Context Legal Term Definitions

As a first-time renter reading a lease, I want to see legal terms like "indemnification" or "force majeure" explained in plain language when they appear in my document, so that I don't have to look them up separately.

Acceptance Criteria: Legal terms in the document are automatically detected and underlined. Hovering or clicking a term shows a plain-language definition. Definitions are contextualized to how the term is used in the specific document, not just a generic dictionary entry. A full glossary panel lists all detected terms alphabetically.

MVP Feature 6 — Document Upload & Management

US-08: Upload and Manage Documents

As a user, I want to upload PDF, DOCX, or plain-text documents and manage them in a simple library, so that I can return to previous analyses.

Acceptance Criteria: Supported formats: PDF, DOCX, TXT, RTF. Maximum file size: 25 MB. Documents can be renamed, tagged, and deleted. Deleting a document removes all associated data (text, embeddings, analyses). Upload progress is shown with estimated processing time.
US-09: Paste Text Directly

As a user reviewing terms of service on a website, I want to paste the text directly instead of uploading a file, so that I can quickly analyze web-based documents.

Acceptance Criteria: A text-paste area is available alongside the file uploader. Pasted text is processed with the same analysis pipeline as uploaded files. The system auto-detects document structure (headings, numbered sections) from pasted text.

LLM Prompt Templates

Each analysis capability uses a structured prompt template. Templates include a system prompt (consistent across all calls) and a task-specific user prompt. The system prompt establishes the safety guardrails, and the task prompt provides the specific instructions and document context.

System Prompt (All Calls)

You are LegalLens, an AI assistant that helps people understand legal
documents. You provide information and explanations — you do NOT provide
legal advice.

CRITICAL RULES:
1. Always base your analysis on the specific document provided.
   Never fabricate clauses or terms not present in the document.
2. If the document does not address a question, say so clearly.
3. Never state that something is "legally binding" or make
   definitive legal judgments. Use phrases like "this clause
   appears to," "based on the document's language," and
   "a licensed attorney could confirm whether."
4. When you identify risks or obligations, flag them clearly but
   frame them as observations, not legal conclusions.
5. If asked for jurisdiction-specific legal advice, decline and
   recommend consulting a local attorney.
6. Assign a confidence level to every output:
   - HIGH: clear, unambiguous language in the document
   - MEDIUM: reasonable interpretation but some ambiguity
   - LOW: significant ambiguity or missing context
7. Always cite the specific section, clause, or line numbers
   that support your analysis.

Security & Privacy

Data Protection

Encryption

All data encrypted in transit (TLS 1.3) and at rest (AES-256). Document storage uses server-side encryption with per-user keys. Database fields containing document text use column-level encryption.

Data Minimization & Retention

Documents are processed and chunked on upload; raw files are stored encrypted and can be deleted by the user at any time. When a user deletes a document, all associated data is removed: the original file, extracted text, embeddings, analysis results, and Q&A history. A hard purge runs within 24 hours of deletion. No document data is retained for model training.

Local Processing Option

Users can opt for local-only processing where document parsing and chunking happen entirely on the client or self-hosted instance. Only the assembled prompt (containing document excerpts, not the full file) is sent to the LLM API. The LLM provider's data retention policies are disclosed to the user, with a link to Anthropic's usage policy confirming that API inputs are not used for training.

Authentication & Authorization

User Authentication

OAuth 2.0 via Clerk/Auth0 with support for Google, Microsoft, and email magic links. Session tokens use short-lived JWTs (15-minute expiry) with refresh tokens (7-day expiry, rotated on use). Rate limiting per user: 50 analysis requests/hour, 200 Q&A turns/hour.

Document Isolation

Strict tenant isolation: every database query filters by user_id. Object storage uses per-user prefixes with IAM policies preventing cross-user access. Vector search is scoped to the user's own document embeddings only.

LLM Safety Guardrails

Input Guardrails

Prompt injection detection on all user inputs (Q&A queries, document text). The system prompt is immutable and prepended server-side — users cannot override it. Document text is sanitized to remove executable content before inclusion in prompts.

Output Guardrails

Post-processing checks every LLM response for: definitive legal conclusions (blocked and rephrased), jurisdiction-specific advice (flagged with disclaimer), missing confidence levels (injected as "LOW" with a note), and hallucinated section references (cross-checked against actual document structure). All guardrail interventions are logged for quality monitoring.

Compliance Considerations

Regulatory Alignment

The platform is designed with GDPR and CCPA compliance in mind: right to deletion (fully implemented), data portability (export all user data as JSON), consent management (explicit opt-in for cloud processing), and processing records (audit log of all data operations). For jurisdictions where AI-generated legal information has specific disclosure requirements, the disclaimer system is configurable per region.

Phased Roadmap

Phase 1 — MVP Weeks 1–8

Weeks 1–2: Foundation

Project setup: Next.js frontend, FastAPI backend, PostgreSQL + pgvector, S3/MinIO storage. Authentication via Clerk. CI/CD pipeline. Document upload and parsing pipeline (PDF, DOCX, TXT) using Apache Tika + PyMuPDF. Text extraction, section detection, and chunking logic. Embedding generation and vector storage.

Weeks 3–4: Core Analysis

Prompt orchestration layer with template management. Guardrail engine (system prompt injection, output validation, disclaimer attachment). Plain-language summary generation (brief and detailed modes). Clause detection, categorization, and risk assessment. Confidence scoring and source reference linking.

Weeks 5–6: Q&A and Glossary

RAG pipeline for contextual Q&A: vector retrieval, context assembly, answer generation. Conversation history management within sessions. Legal term detection and glossary generation (contextual definitions). Action item and checklist extraction. Guardrail refinement based on initial testing.

Weeks 7–8: Polish and Launch

Frontend integration: document viewer with clause highlighting, analysis panel tabs, Q&A interface. Document management (library, rename, delete with full data purge). Disclaimer system (persistent bar, per-output disclaimers). Accessibility audit (WCAG 2.1 AA). Performance optimization (target: summary in <15s for 20-page docs). Beta launch with feedback collection.

Phase 2 — Compare & Customize Weeks 9–16

Weeks 9–11: Contract Comparison

Side-by-side document comparison engine: clause-level alignment, diff detection, change categorization. Comparison UI with synchronized scrolling, change highlighting, and impact summaries. Support for comparing two different documents or two versions of the same document.

Weeks 12–14: Jurisdiction & Templates

Jurisdiction-aware analysis templates (US states, UK, EU, Canada, Australia). Document type templates with type-specific analysis focuses (lease → habitability clauses; NDA → scope and duration; employment → non-compete and IP assignment). Named entity recognition for parties, dates, amounts, and locations. Redaction tool for PII before sharing analysis results.

Weeks 15–16: Quality & Confidence

Confidence calibration: compare LLM-assigned confidence with human review data to improve accuracy. Expanded guardrails based on Phase 1 usage patterns. Multi-document analysis: ask questions across a set of related documents. Export improvements: PDF reports, structured JSON, markdown.

Phase 3 — Collaborate & Integrate Weeks 17–24

Weeks 17–19: Collaboration

Multi-user workspaces with role-based access (viewer, editor, admin). Annotation system: highlight text, add comments, tag team members. Review workflows: assign documents for review, track status, collect feedback. Shareable analysis links (read-only, with configurable redaction).

Weeks 20–22: Integrations

E-signature integration (DocuSign, HelloSign): analyze before signing, track post-signature obligations. Document management connectors (Google Drive, Dropbox, SharePoint): import directly from cloud storage. Notification system: deadline reminders for extracted action items. API access for programmatic document analysis.

Weeks 23–24: Analytics & Scale

Usage analytics dashboard: documents analyzed, questions asked, most common document types. Analysis quality metrics: user satisfaction ratings, guardrail trigger rates, confidence accuracy. Performance optimization for high-volume users. Horizontal scaling for the analysis pipeline. SOC 2 Type II preparation.
